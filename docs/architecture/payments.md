# Payments and checkout adapters

Sprint 0 makes no provider calls, accepts no payment details and has no webhook endpoint. GCash must be offered through an approved Philippine payment provider with merchant underwriting and supported hosted checkout. Provider selection and authorization, fees, settlement account and refunds are unresolved. COD is a separate payment method with collection and reconciliation states, not an automatic paid result.

Define a server-only PaymentProvider adapter: createAttempt(orderSnapshot,idempotencyKey), verifyWebhook(rawBody,headers), queryStatus(reference), cancelAttempt(reference), refund(reference,amount,key). Normalize provider states into created → pending → succeeded / failed / expired / cancelled; succeeded may enter partially_refunded or refunded through explicit refund records. Keep order and payment state machines separate. COD transitions pending_collection → collected / refused with authorized operational evidence.

The server calculates totals from authoritative variants, discounts, shipping and tax; the browser supplies intent only. Use hosted/tokenized checkout, HTTPS, strict return URL allowlists and redirect state nonces. Browser return URLs never establish success. Record an attempt with an idempotency key before the external call; reconcile timeouts by key/reference rather than charging again. Verify amount, currency, merchant account and order linkage before marking paid.

Webhooks verify the raw body signature and provider timestamp/replay window before parsing and persistence; secrets stay server-side and rotate safely. Unique (provider,event_id) prevents duplicate processing. Within a transaction lock payment/order/reservation, reject invalid regressions, append a redacted event and update state exactly once. Acknowledge already processed duplicates. On transient failure return retryable status; reconcile missed, delayed and out-of-order events with authenticated provider queries. Signature design is provider-specific and must follow the selected provider's documentation.

Reservation expiry races and payment success use the same row lock order. Late payments require stock revalidation or refund/manual review. Cancellation must coordinate provider void and stock release without double release. Refunds need a separate immutable ledger, provider idempotency, amount ceilings, partial refund allocation and reconciliation; the Sprint 0 schema is not a complete accounting system. Validate shipping addresses on the server, quote fees per serviceable region, snapshot addresses and protect PII. Provider contracts, production credentials, webhook verification and race/retry integration tests block launch.
