# Product-neutral catalog

Products are descriptive entities; variants are purchasable SKUs with their own integer price, currency, active state, stock and optional media. Even a product without visible options gets one default variant. Categories are an adjacency tree with no fixed depth. product_categories allows cross-listing; collections are curated ordered groupings rather than category substitutes. A product may be draft, published or archived and independently public, unlisted or private. Publication must validate required attributes and complete active variants.

Category-independent option types and values model multiple dimensions (size/color, capacity/finish, length/material). variant_option_values allows exactly one selected value per dimension. Composite foreign keys prevent mixing variants and option values from different products. option_signature is a server-generated canonical, sorted dimension/value encoding and is unique within the product. Complete option coverage is validated in the publishing transaction; the schema alone does not prove completeness.

Fixtures demonstrate handbags, shoes, clothing, jewelry, electronics and home products with fictional names, PHP prices and stock. ProductDetail and LiveSelling render arbitrary option labels and specifications. Bag-specific details exist only as sample attribute content and storefront copy, never schema columns.

Sprint 0 filtering supports text, category, maximum variant price, curated or price sorting, and session-only saved pieces. Production repository queries must restrict seller, publication and visibility first; use parameterized search, pagination and stable tie breakers. Add a PostgreSQL full-text GIN index and explicit category/price indexes after representative query analysis. Attribute facets use typed attribute values and filterable metadata. Category paths, inherited filters, selectable facets, URL filter state and large-catalog pagination are planned, not currently implemented. Displayed starting price and sorting should use the minimum active variant price in the server projection.
