# Sprint 0 security review

Sprint 1 supplement: `authentication.md` distinguishes isolated boundary tests from live security controls. Static account pages accept no input; no server handler is deployed. Real refresh serialization, secret management, provider timing/enumeration, revocation, account-level limits, least privilege and audit integrity still require integration testing. Do not use a passing mock-provider suite as release authorization.

Implemented boundary: client-only fictional catalog; no credentials, APIs, persistence, uploads, authentication, orders, payment processing or external live connections. React escapes text. Zod checks demo selection quantities and IDs; demo quantity cannot exceed the selected stock. Netlify headers declare CSP, frame denial, MIME sniffing protection, restrictive device permissions and referrer policy. Validate effective response headers after an authorized deployment; configuration is not a deployed verification. No security control is claimed for a nonexistent backend.

The dormant schema uses seller-owned composite keys, foreign keys, uniqueness and bounds. It does not enforce read authorization or complete publication/state rules. Before enabling APIs: verify authentication server-side; derive seller from trusted context; check seller membership/customer ownership; enable tested RLS; strictly validate requests and outputs; reject unknown fields; paginate/limit queries; parameterize SQL; use safe errors with correlation IDs; log only redacted structured metadata. Protect cookie mutation routes with CSRF/Origin checks. Never trust order totals, role flags, price, inventory, object key or seller_id from the browser.

Use shared durable rate limits for login, catalog searches, checkout, webhooks, upload initiation and chat; local process counters are insufficient. Webhooks need raw-body signature verification, replay windows, event uniqueness and transaction-locked transitions. Audit admin, stock, order, refund, media and moderation mutations; append-only logs need restricted grants, retention and monitoring. Use least-privilege runtime roles, secret rotation, dependency scanning and backup/recovery drills. No client-exposed secrets or raw provider payload storage.

Media ownership, quarantine, byte validation and processing limits are detailed in product-media.md. Restrict outbound fetching and validate every redirect if remote imports are introduced. Add consent, data export/deletion, retention schedules and approved merchant legal/privacy policies before real customer data. External Unsplash/Google resources create third-party requests; self-host approved licensed assets/fonts before a privacy-sensitive launch.

Known gaps: browser/manual screen-reader and contrast review, integration/concurrency/RLS tests, app authentication, rate limiting, audit runtime, automated security monitoring, provider approvals, final legal policies and production asset licensing. Sprint 0 is not a production commerce security sign-off. See the final audit for actual automated test and dependency audit results.
